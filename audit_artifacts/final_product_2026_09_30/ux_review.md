# UX and accessibility review — current source

**Scope.** Read-only review of the current `HEAD` product surface listed in `inventory.md`. This review owns Arabic/RTL presentation, localization presentation, responsive layout and text scale, contrast/touch targets, semantics/focus/screen-reader experience, Quran readability, discoverability, and child/elderly experience. It does not assess state correctness, religious-content correctness, release configuration, or device integration outcomes.

**Evidence limit.** Findings below are source-confirmed unless labelled **unverified**. No current-HEAD device run or accessibility-service traversal was available to this reviewer; screenshots/XML from an earlier APK must not be treated as confirmation for the current source.

## Findings

| Severity | Feature / affected user | Exact problem and evidence | Expected behavior and remedy |
|---|---|---|---|
| **P2 Major** | All pushed full-screen flows; people who enable Android Remove animations, including motion-sensitive children and elderly users | The app installs `_FadeSlideTransitionBuilder` for Android at [app_theme.dart:296](D:/Flutter/talia_quran/lib/core/theme/app_theme.dart:296). Its `buildTransitions` always creates a `CurvedAnimation` and `SlideTransition` at [app_theme.dart:314](D:/Flutter/talia_quran/lib/core/theme/app_theme.dart:314), without checking `MediaQuery.disableAnimationsOf(context)`. Several feature surfaces do honor this setting, so navigation remains the inconsistent, unavoidable animation path. | With Remove animations enabled, route transitions must be immediate or use `Duration.zero`. Gate this transition builder on `MediaQuery.disableAnimationsOf(context)` (and return `child`), then test each shell tab and pushed flow with the setting on. |
| **P2 Major** | Quran browse and Juz selection; large-text and low-vision users | The Quran page deliberately clamps the system scale to `1.5` at [quran_page.dart:226](D:/Flutter/talia_quran/lib/features/quran/presentation/pages/quran_page.dart:226), and the Juz grid repeats the same cap at [juz_grid_view.dart:32](D:/Flutter/talia_quran/lib/features/quran/presentation/widgets/juz_grid_view.dart:32). At Android 200% text size, labels therefore render at only 150%, even where the page uses `Wrap`, adaptive grid columns, and variable app-bar height. This is a verified accessibility override, not merely a device risk. | Respect the requested scaler. Let the existing adaptive layout select fewer columns/increase extents, allow the reciter label to wrap or move to its own row, and test 200% and 300% on 320dp phone and tablet widths. |
| **P2 Major** | Azkar category reader; elderly users and users with motor impairment on narrow phones | When width is below 360dp, the reader explicitly changes both header `IconButton`s to `minWidth/minHeight: 36` and compact density at [azkar_category_page.dart:348](D:/Flutter/talia_quran/lib/features/azkar/presentation/pages/azkar_category_page.dart:348). Back and font-size controls are primary actions in a long reading flow. A 36dp target is below the 48dp Material/Android accessibility target and becomes harder precisely on compact devices. | Keep independently tappable controls at least 48×48dp. Collapse secondary controls into the existing overflow menu on narrow screens while retaining Back at 48dp; confirm at 320dp with large text. |
| **P2 Major** | Tutorial guide category filter; elderly/motor-impaired users | `_CategoryChips` constrains the entire interactive `ChoiceChip` row to 36dp at [tutorial_guide_page.dart:303](D:/Flutter/talia_quran/lib/features/tutorial_guide/presentation/pages/tutorial_guide_page.dart:303). Its parent constraint wins over the chip’s normal comfortable hit area. This makes every category selector undersized. | Use a minimum 48dp row/target (or a wrapped filter list), preserving horizontal scrolling and visible selected state. Add a widget assertion for the effective tap target. |
| **P3 Minor** | Error/empty recovery banners; users who need to dismiss an error before continuing | The optional close action is explicitly styled with `minimumSize: Size(0, 32)` and compact visual density at [error_info_banner.dart:76](D:/Flutter/talia_quran/lib/core/widgets/error_info_banner.dart:76). This shared component appears in authentication and other recovery surfaces, so it spreads a 32dp dismissal target across error handling. | Make the close action 48×48dp, or make the whole banner dismissible with a labelled 48dp affordance. Keep its semantic label and verify keyboard/focus traversal. |
| **P3 Minor** | Quran Mushaf and Kids Quran reader; TalkBack users | The actual Quran visual page is passed directly to third-party `qcf.QuranSinglePageWidget` at [app_quran_page_view.dart:160](D:/Flutter/talia_quran/lib/features/quran/presentation/widgets/app_quran_page_view.dart:160). The application wrapper adds no semantic page label, ayah headings/actions, reading order, or alternate structured text; its only surrounding behaviour is forced RTL and gesture zoom at [app_quran_page_view.dart:117](D:/Flutter/talia_quran/lib/features/quran/presentation/widgets/app_quran_page_view.dart:117). Consequently a TalkBack user has no application-owned guarantee that a Mushaf page exposes verse text or can reach the long-press ayah actions. | Provide an app-owned semantic page/ayah tree or an accessible list/reader mode tied to the same page and selected ayah actions. Test with TalkBack: page announcement, verse order, bookmark/play/share action names, double-tap activation, and focus after page turn. Do not claim accessibility from the third-party visual widget without that test. |
| **P3 Minor** | Azkar and Smart Wird counting; screen-reader users | The main reading card uses a bare `GestureDetector` for tap-to-count and long-press-to-undo at [azkar_category_page.dart:596](D:/Flutter/talia_quran/lib/features/azkar/presentation/pages/azkar_category_page.dart:596) and [smart_wird_page.dart:498](D:/Flutter/talia_quran/lib/features/azkar/presentation/pages/smart_wird_page.dart:498). The visible instruction communicates a long press, but there is no semantic custom action for undo. The dial supplies button/value semantics at [smart_wird_page.dart:609](D:/Flutter/talia_quran/lib/features/azkar/presentation/pages/smart_wird_page.dart:609), leaving the distinct undo gesture undiscoverable/non-operable through standard screen-reader actions. | Expose a labelled increment button and a separate labelled Undo control or `CustomSemanticsAction`; announce the changed count with a live region. Keep the gesture as a shortcut, not the only undo path. |
| **P3 Minor** | Kids gamified journey; child and screen-reader user | A stage is one large `InkWell` ([kids_house_card.dart:53](D:/Flutter/talia_quran/lib/features/memorization_plus/presentation/widgets/kids_house_card.dart:53)) containing status, ayah range, progress, stars, and CTA-style content, but has no explicit semantic label/state/hint. The visible footer is decorative and does not call its `onTap` at [kids_house_card.dart:476](D:/Flutter/talia_quran/lib/features/memorization_plus/presentation/widgets/kids_house_card.dart:476). TalkBack will depend on incidental descendant text rather than receiving “stage N, locked/current/review, progress, activate”; a child cannot tell why a locked house cannot open through accessibility output. | Wrap each card in one semantic button with localized label/value/hint, include locked/current/review state and progress, and make a locked activation announce the prerequisite. Exclude duplicate decorative descendants. Test focus order across the journey map. |

## Coverage and verified presentation strengths

The following current-code surfaces were inspected for presentation/accessibility: splash and onboarding/audience fork; auth/password recovery; shell navigation and home cards; Quran browse/search/bookmarks/reader/reader sheets/audio UI; adult practice, plan, listening review, V2 session/remediation/completion; kids home/journey/stage/listen/completion and guardian/family views; progress/achievements/certificate and share sheet; Khatmah setup/dashboard/history/completion/dua; Azkar hub/category/general/smart wird; settings and prayer/notification/kids/about/privacy subpages; tutorial guide; and contextual Talia, sharing, error/loading/empty widgets.

Positive source evidence: the application registers Arabic and English localizations and the Material/Widgets/Cupertino delegates in [app.dart:172](D:/Flutter/talia_quran/lib/app.dart:172); directional APIs are used for primary app-shell layout and the Mushaf preserves RTL independently of UI locale ([app_shell.dart:93](D:/Flutter/talia_quran/lib/core/widgets/app_shell.dart:93), [app_quran_page_view.dart:117](D:/Flutter/talia_quran/lib/features/quran/presentation/widgets/app_quran_page_view.dart:117)); the wide shell intentionally substitutes a navigation rail at 600dp ([app_shell.dart:93](D:/Flutter/talia_quran/lib/core/widgets/app_shell.dart:93)); normal themed buttons have a 48dp minimum ([app_theme.dart:101](D:/Flutter/talia_quran/lib/core/theme/app_theme.dart:101)); and many reader controls supply tooltip/48dp sizing, including the reader top bar ([reader_top_bar.dart:69](D:/Flutter/talia_quran/lib/features/quran/presentation/widgets/reader_top_bar.dart:69)). Quran reader includes zoom, a focus-mode exit control, font selection for Azkar, and the Khatm dua has explicit size controls, all helpful for readability.
