## Overall Impression

This is a disciplined, well-engineered UI codebase with a real committed design world and unusually strong error prevention and recognition support. The biggest opportunities are no longer "add polish" — they are (1) closing the gap between the committed token system and the ~180 off-system literals that will eventually cause a contrast or dark-mode regression, (2) making the offline-first promise *visible*, and (3) trimming the home surface so the one daily practice decision stays dominant.

## What's Working

- **Error prevention is genuinely excellent.** Route guards validate surahId 1–114 and normalize/clamp page numbers; the memorization path choice requires an explicit confirm sheet with "you can change later"; the V2 session blocks back with a leave-confirmation; azkar fails closed to an "under review" state rather than showing unapproved religious content.
- **Recognition over recall everywhere.** Five labeled tabs, tooltips on all icon buttons, resume cards, reader quick-nav with last-read page, and a searchable, categorized tutorial guide.
- **A real, specific visual identity.** The night-sanctuary world (committed night ground, gold reserved for meaning, Amiri/Noto Naskh pairing, mushaf parchment) is consistently described in code comments and enforced through HomeSkin/KidsTheme token files — the onboarding finish-review discipline shows.

## Priority Issues

### [P1] English locale is silently broken in secondary surfaces
**Why it matters:** PRODUCT.md commits to Arabic-first *with English localization*. Users who switch to English still see Arabic in Azkar (hero subtitles, tasbeeh, section header), the tutorial guide (header, search hint, empty state), general-azkar favorites/empty states, the azkar font-scale sheet, and several settings tiles. Mixed-language UI reads as unfinished and erodes trust for exactly the users who need English.
**Fix:** Route every user-facing string through `AppLocalizations`; add a lint/test that fails on Arabic literals outside l10n files; keep splash tagline and Quranic text intentionally Arabic (documented exceptions).
**Suggested command:** `$impeccable harden` (then `$impeccable clarify` for the strings themselves)

### [P1] Token drift will eventually produce a contrast or dark-mode regression
**Why it matters:** DESIGN.md defines a strict teal/gold semantic system, but 109 raw hex literals and 71 font-size literals bypass it — splash's private palette, Azkar's one-off purple/orange, Progress's ad-hoc hero gradients, one-off hexes in hub/v2/khatmah surfaces. Any future theme change or dark-mode pass must re-audit every literal; the Meaningful Gold Rule is unenforceable where colors are hard-coded.
**Fix:** Consolidate one-off colors into `AppColors` (or the surface-skin pattern already proven in home_skin); replace fontSize literals with the type scale; add a custom lint banning `Color(0x…)` and `fontSize:` outside theme files.
**Suggested command:** `$impeccable extract` → `$impeccable polish`

### [P1] The offline-first promise is invisible
**Why it matters:** The product's core trust claim is offline reliability, yet the UI never states connectivity or sync state. Resume-sync runs silently; its only visible failure path is an account-data-discarded snackbar. On poor connections users can't tell whether their progress saved — the exact moment trust matters most.
**Fix:** A quiet connectivity/sync chip in the home header (synced / syncing / offline — progress is safe on device); an explicit "saved locally" reassurance after session commits; a retry action on failed resume-sync instead of silence.
**Suggested command:** `$impeccable harden`

### [P2] Home still stacks ~10 sections before the footer
**Why it matters:** Header → primary action → contextual slot → 4 tiles → challenge → journey rings → ayah of day → activity feed → parent children → quick access. The unified hero action fixed primacy, but the tail competes for the same decision and the primary action sits below a tall brand header, hurting thumb reach (Casey) and diluting the calm promise (heuristic 8).
**Fix:** Collapse activity feed + quick access into one compact section or progressive disclosure; consider moving ayah-of-day below the fold by default; keep header ≤ ~40% viewport so the hero action lands in the thumb zone.
**Suggested command:** `$impeccable distill` (or `$impeccable layout`)

### [P2] Text-scale ceiling (1.35) caps accessibility
**Why it matters:** `app.dart` clamps system text scaling to 0.85–1.35. Low-vision users typically need 1.5–2.0; layouts already adapt (`textScale > 1.3` switches to single-column on home tiles), so the cap is conservative relative to the adaptation work already done.
**Fix:** Verify key screens at 1.5–2.0 (home, reader chrome, settings, session), then raise or remove the cap; keep per-component `MediaQuery.withClampedTextScaling` only where genuinely necessary (hero brand lockup).
**Suggested command:** `$impeccable audit` → `$impeccable adapt`

### [P3] Mixed interaction primitives
**Why it matters:** 8 `GestureDetector` sites (login sign-in/up toggle, azkar category rows, achievement tiles, mini-player) lack the ripple/semantics parity of the InkWell pattern used in 62 other files; the login toggle compensates with `Semantics` but has no pressed feedback.
**Fix:** Standardize on InkWell/Button primitives (or a shared `TaliaToggle` chip) with haptics + semantics.
**Suggested command:** `$impeccable polish`

### [P3] Copy tone inconsistency
**Why it matters:** Notification samples mix MSA brand voice with Egyptian colloquial ("يلا", "متكسلش") in the same surface; brand commitments say calm and respectful.
**Fix:** Pick one register (MSA recommended for brand copy; dialect only in deliberately warm kids contexts) via `$impeccable clarify`.

## Persona Red Flags

**Alex (impatient power user):** Fast paths exist (hero action, alternatives sheet, resume, re-tap-tab scroll-to-top). Red flag: no quick jump to "my memorization session" from the reader; he must traverse hub → practice.
**Jordan (first-timer):** Tutorial slot, quick-start card, guest-first, skippable onboarding — strong. Red flag: first visit to Azkar shows a content "under review" dead-end if bundles fail, with retry but no explanation of what azkar are.
**Sam (accessibility-dependent):** Semantics, tooltips, disable-animations honored in 13 files, 48–56px targets. Red flags: the 1.35 text-scale ceiling; `GestureDetector` sites without pressed-state semantics; kids journey color-only status (locked/complete) needs icon or label verification.
**Hafidh-in-progress learner (project persona):** The unified journey engine answers "what now?" well. Red flag: nothing tells her whether last night's sync kept her review schedule intact when she practices offline at dawn.
**Guardian (project persona):** Parent slot, family dashboard with auth guard, consent-based linking. Red flag: parent tools appear on the learner's home rather than a dedicated space, mixing audiences on one scroll.
**Child:** Kids world is consistent (own nav, big targets, mascot, 96px clearance). Red flag: kids bottom-nav "Home" routes out of the kids world to the main app home — a likely trap for a 7-year-old.
