# إصلاح عاصفة تكرار المهام الخلفية (Background Task Retry Storm)

## المشكلة
المهام الخلفية (Workmanager) تعيد التهيئة بشكل مفرط لسببين:
1. **PGRST202 ما زال يحدث** — ملف SQL للـ bookmarks لم يُطبَّق بعد على Supabase (يتطلب منك: Dashboard → SQL Editor → تشغيل `supabase/apply_bookmark_functions.sql`)
2. **NullPointerException جديد**: `AppInitializer.initialize(background: true)` يشغّل خطوات الإشعارات (`_initNotifications` + `_scheduleFirstLaunchNotifications` → `cancelStreakAlert()`) داخل الـ headless engine حيث لا يوجد Activity context → الـ plugin ينفجر → المهمة تُبلّغ بالفشل → Workmanager يعيد جدولتها بـ backoff (وفي اللوج: `reschedule = true`)

## الإصلاح المقترح (تغيير واحد في ملف واحد)

**`lib/core/services/app_initializer.dart`** — تخطي خطوتي الإشعارات (3 و4) كلياً عند `background: true`:

```dart
// Steps 3 & 4: Notifications — foreground only. The notification
// plugin needs an Activity context that headless Workmanager engines
// don't have; calling it there throws NullPointerException, which
// makes the background task report failure and get retried forever.
if (!background) {
  onProgress?.call('جارٍ إعداد التنبيهات...', 0.6);
  await _initNotifications();

  onProgress?.call('جارٍ ضبط المواعيد...', 0.8);
  await _scheduleFirstLaunchNotifications();
}
```

المهام الخلفية لا تحتاج الإشعارات أصلاً — جدولة الإشعارات تحدث في الواجهة فقط، والمهمة الخلفية تنفّذ الـ cloud sync فقط.

## التحقق

- `flutter test` — كل الاختبارات ناجحة

## النتيجة المتوقعة بعد الإصلاح + تطبيق SQL
- المهمة الخلفية تكتمل بنجاح (return true) → لا retry من Workmanager
- الـ bookmark pull ينجح → الطابور يفرغ → لا إعادة جدولة
- يبقى فقط init واحد لكل مهمة خلفية **مشروعة** — وهذا طبيعي بحكم التصميم
