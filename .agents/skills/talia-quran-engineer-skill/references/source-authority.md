# Source Authority

**Current official evidence beats remembered knowledge.**

When freshness matters, prefer this hierarchy:

1. official Flutter/Dart documentation, release notes, breaking-change guides, and SDK tooling output.
2. official Supabase documentation, SDK migration guides, database/platform documentation, and project tooling evidence.
3. official Android documentation and Google Play policy/target requirements.
4. official Apple documentation and App Store policy/platform requirements.
5. official package repository/changelog and pub.dev metadata.
6. trusted maintainer issue trackers and release discussions.
7. community discussion only as supporting evidence, never as the sole authority for release, security, or migration decisions.

Record the date/source for important external facts. Do not claim a version, policy, deprecation, or recommended integration is current without checking an authoritative source during that task.
