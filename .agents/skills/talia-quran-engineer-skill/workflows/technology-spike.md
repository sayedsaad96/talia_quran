# Technology Spike

1. State a falsifiable hypothesis and the Talia problem it could solve.
2. Build an isolated prototype/benchmark; spike code is not production architecture by default.
3. Use representative inputs and explicit success metrics.
4. Apply privacy, Quran-correctness, platform, latency, maintenance, and cost constraints.
5. Record results as `Adopt`, `Discard`, or `Continue assessment`.
6. Promote to production planning only after evidence supports integration value and risk.
