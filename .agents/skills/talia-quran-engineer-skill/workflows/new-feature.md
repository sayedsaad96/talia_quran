# New Feature Workflow

1. Define the user problem and desired outcome.
2. Search verified living knowledge and the current repository for existing related capabilities.
3. Inspect the real implementation and data/state boundaries.
4. Classify the idea as `BUILD`, `EXTEND`, `DEFER`, or `REJECT`.
5. Map affected systems, risk level, stored data, platform/backend impact, and rollback needs.
6. Define acceptance criteria, failure hypotheses, and regression risks.
7. Implement test-first where practical using the smallest safe change.
8. Run relevant runtime validation and evidence-based verification.
9. Refresh verified knowledge, risks, product debt, or opportunities that changed.
