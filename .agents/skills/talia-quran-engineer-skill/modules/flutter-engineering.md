# Flutter Engineering

Inspect the current Talia architecture, state management, navigation, persistence, platform configuration, and nearby tests before changing Flutter code.

- Verify official Flutter/Dart guidance when freshness matters.
- Check Android/iOS/platform impact for SDK or plugin changes.
- Do not migrate simply because a newer Flutter pattern exists.
- Prefer built-in Flutter/Dart capability when it solves the problem cleanly.
- Preserve current project conventions unless evidence shows measurable pain.
- For lifecycle, rendering, async, isolate, and plugin work, validate the real runtime path rather than assuming static correctness.
