## 1. الملخص التنفيذي والرؤية (Executive Summary & Vision)

يهدف هذا المشروع إلى تحويل مسار الأطفال الخاص بالمهام وحفظ القرآن الكريم في تطبيق "تالية" من واجهات بطاقات تقليدية إلى **عالم ألعاب مغامرات ثلاثي الأبعاد (2.5D / Isometric Gamified Adventure)** شبيه بتجارب الألعاب العالمية الرائدة (مثل Nintendo و Duolingo)، ليكون تجربة بصرية وسمعية مشوقة تجعل الطفل يتشوق لحفظ كل آية وإتمام المهام اليومية.

### المبادئ الجوهرية للتصميم:
1. **الأصالة والوقار القرآني:** مسار الحفظ الصوتي يظل نقياً وسريعاً وخالياً من أي تعقيد أو تشتيت للطفل.
2. **لعبة حقيقية (Game Feel):** بيئات وعوالم متغيرة (Dynamic Biomes)، مسار حجري ثلاثي الأبعاد متعرج، صناديق مفاجآت، وقلعة مراجعة وقصر ختام السورة.
3. **رفيق رحلة حي (Interactive Hero Mascot):** تجسيد الطفل أو شخصية "تالية" كأفاتار حي يقف على الخريطة، يتفاعل باللمس، ويقفز بقوس فيزيائي كرتوني عند الإنجاز.
4. **تغذية سمعية وحسية فورية (Juicy Audio & Haptics):** نغمات رنين النجوم، قفز الأفاتار، فتح الصناديق، واحتفالات الفوز مع اهتزازات لمسية ترضي حواس الطفل.
5. **كفاءة وأداء فائق (60-120 FPS):** استخدام Canvas والطبقات المعزولة (`RepaintBoundary`) بدون محركات ألعاب ثقيلة لضمان العمل بسلاسة تامة على كافة الهواتف الاقتصادية ودون استهلاك للبطارية.

## 2. المعمارية العامة ومحرك العوالم (Architecture & Dynamic Biome Engine)

### 2.1 فصل الطبقات النظيف (Clean Layer Isolation)
* **طبقة النطاق وإدارة الحالة (Domain & State - بدون تعديل جوهري):**
  * الإبقاء الكامل على `KidsJourneyCubit`، `KidsJourneyStage`، و `MemorizationPlusRepository` وكيانات `Isar` دون كسر لأي بيانات سابقة أو مسارات مزامنة سحابية.
* **طبقة محرك الألعاب والبيئات (Game & Biome Engine - جديدة):**
  * `KidsBiomeEngine`: إدارة وتحديد ثيم العالم بناءً على رقم السورة أو الجزء.
  * `KidsAudioFeedbackService`: خدمة إدارة المؤثرات الصوتية للألعاب والاحتفالات باستخدام `just_audio`، مع حفظ حالة الكتم في `SharedPreferences` عبر المفتاح `kids_sfx_muted`.
* **طبقة الواجهات المرئية (Game Presentation Components):**
  * `DynamicBiomeBackground`: خلفية تفاعلية بطبقات Parallax متدرجة تتغير حسب العالم.
  * `IsometricJourneyPath`: كانفاس مخصص لرسم المسار الحجري ثلاثي الأبعاد والمنصات.
  * `InteractiveMapNode`: المكونات الثلاثية الأبعاد (بيوت الحفظ، صناديق الكنوز، قلعة المراجعة، قصر الختام).
  * `HeroAvatarController`: محرك حركة وقفز الأفاتار.

### 2.2 جدول تخصيص السور للعوالم (Explicit Biome Mapping)
يبدأ الطفل رحلته في جزء عم تلقائياً بحسب `KidsJourneyCursor` تنازلياً من سورة الناس (114) إلى سورة النبأ (78). يتم توزيع السور على العوالم الثلاثة بدقة:

|---|---|---|---|
| **عالم جزر السحاب والنور (Cloud & Light Realm)** | `93..114` (22 سورة) | من الضحى إلى الناس | سماء تركوازية مشرقة (`#0284C7` ➔ `#38BDF8`)، سحب بيضاء عائمة، منصات بلورية زرقة وذهبية (`#F59E0B`) |
| **عالم واحة الفردوس والحدائق (Oasis & Gardens Realm)** | `78..92` (15 سورة) | من النبأ إلى الليل | أخضر زمردي منعش (`#059669` ➔ `#10B981`)، نخيل وتلال كرتونية، جداول مياه، منصات طينية وخشبية |

## 3. خريطة المغامرة ومكونات الـ 3D (Adventure Map & Isometric Nodes)

### 3.1 هيكل المسار (The 3D Winding Path)
* استبدال الكروت المستطيلة بمسار مرسوم عبر `CustomPainter` يربط بين منصات ألعاب مجسمة (Squashed Cylinder 3D stepping tiles) بارتفاع وظل سفلي تفاعلي.
* المسار يتحرك بسلاسة متعرجة من اليمين إلى اليسار صعوداً بنسب مئوية مرنة تتكيف مع كافة مقاسات الشاشات (`LayoutBuilder`).

### 3.2 استنتاج أنواع العقد دون تعديل طبقة النطاق (Node Type Inference Logic)
للحفاظ على نظافة الـ Domain Model (`KidsJourneyStage`)، يتم اشتقاق نوع العقدة في طبقة العرض (Presentation Layer) حصراً عبر الدالة النقية:

```dart
KidsMapNodeType resolveNodeType({
  required KidsJourneyStage stage,
  required int totalStagesInSurah,
}) {
  // 1. إذا كانت مرحلة مراجعة وتثبيت
  if (stage.status == KidsJourneyStageStatus.needsReview) {
    return KidsMapNodeType.reviewFortress;
  }
  // 2. إذا كانت المرحلة الأخيرة في السورة ومكتملة
  if (stage.stageNumber == totalStagesInSurah && stage.status == KidsJourneyStageStatus.completed) {
    return KidsMapNodeType.grandPalace;
  }
  // 3. كل 4 محطات يظهر صندوق كنز سري
  if (stage.stageNumber % 4 == 0) {
    return KidsMapNodeType.mysteryChest;
  }
  // 4. المحطة العادية: بيت حفظ
  return KidsMapNodeType.stageHouse;
}
```

#### تفاصيل مظهر العقد:
1. **بيت الحفظ (Stage House):**
   * *مغلق (Locked):* مظهر بلوري هادئ مع قفل ورقم المرحلة.
   * *حالي (Current):* نوافذ دافئة مضاءة، وهالة ذهبية نابضة (`Pulsing Aura`).
   * *مكتمل (Completed):* سطح مزين براية الفوز وثلاث نجوم ذهبية بارزة.
2. **صندوق الكنز السري (Mystery Treasure Chest):**
   * عند إنجاز المحطة التابعة له، يهتز الصندوق وينفتح غطاؤه بحزمة ضوئية ونجوم إضافية للطفل.
3. **حصن التثبيت والمراجعة (Review Fortress):**
   * قلعة حجرية ثلاثية الأبعاد ترمز لحماية الحفظ وتثبيته.
4. **قصر ختم السورة (Grand Surah Palace):**
   * معلم ضخم في نهاية كل سورة بقباب مذهبة وتاج عائم، يطلق احتفالاً كبيراً وشهادة إتقان ثلاثية الأبعاد.

### 3.3 محرك الأفاتار التفاعلي وحسابات القفز (Hero Avatar & Jump Mechanics)
* **وضعية التنفس والانتظار (Idle Float):** تذبذب عمودي ناعم (4px) مع ظل بيضاوي يتمدد وينكمش بانسجام.
* **التفاعل باللمس:** النقر المباشر على الشخصية يطلق قفزة بهلوانية مرحة وصوتاً تشجيعياً.
* **تسلسل القفز وحساب الإحداثيات (Jump Coordinate & Scroll Pipeline):**
  1. حساب موضع المحطة المصدر (`sourceRect`) والمحطة الهدف (`targetRect`).
  2. إذا كانت المحطة التالية خارج الإطار المرئي، يتم استدعاء `ScrollController.animateTo` بسلاسة لتوسيط المحطة الهدف أولاً.
  3. بعد استقرار التمرير:
     * انضغاط الأفاتار (Squash: `scaleY = 0.85, scaleX = 1.15`) لمدة 150ms.
     * انطلاق مقوس لأعلى عبر Bezier Curve مع تمدد (Stretch: `scaleY = 1.15, scaleX = 0.9`) لمدة 500ms.
     * هبوط ارتدادي ناعم وانفجار نجوم صغيرة مع صوت قفز لطيف (*Boing/Chime*).

### 3.4 التمركز التلقائي (Smart Auto-Focus)
* عند فتح الخريطة، تتحرك الكاميرا تلقائياً بسلاسة لتتمركز حول المحطة الحالية والأفاتار.
* النقر على أي محطة مفتوحة يظهر لوحة سفلية مجسمة (`3D Stage Details Sheet`) تحتوي الآيات المطلوبة وزر انطلاق بارز ثلاثي الأبعاد.

## 4. شاشة المهمة والمؤثرات الصوتية والحسية (Task Screen & Audio Engine)

### 4.1 لوح الحفظ المجسم (3D Quran Tablet)
* عرض الآيات القرآنية الكريمة بخط قرآني فاخر داخل لوح ثلاثي الأبعاد ملموس يطفو في بيئة العالم الحالي.
* أزرار الاستماع والتسجيل بتصميم "Chunky 3D Buttons" تنضغط للداخل فيزيائياً عند الضغط وتحدث اهتزازاً لمسياً (`HapticFeedback.lightImpact`).

### 4.2 ترقية عداد التكرار (3D Glowing Lanterns)
* ترقية عداد التكرار الحالي (النقاط المتحركة `Animated Dots`) إلى **ثلاث قناديل أو نجوم ذهبية ثلاثية الأبعاد**؛ كلما ردد الطفل الآية وأكمل مرة، يشتعل قنديل بنور ذهبي ونغمة رنين (*Ding!*).

### 4.3 تفاعل الأفاتار أثناء التلاوة
* الأفاتار حاضر في ركن الشاشة:
  * يرتدي سماعات لطيفة ويتمايل برأسه بإعجاب مع تلاوة الشيخ وموجات الصوت الملونة.
  * يصفق بحرارة عند انتهاء الطفل من التسميع الصوتي.

### 4.4 خدمة الصوتيات للألعاب (`KidsAudioFeedbackService`)
* ملفات صوتية خفيفة جداً مدمجة محلياً (Zero Latency Offline):
  * `playTap()`: نقرة أزرار ممتعة.
  * `playJump()`: صوت القفز والخطوات على المنصات.
  * `playStarDing()`: رنين النجوم وإضاءة قناديل التكرار.
  * `playChestUnlock()`: حماس وفتح صندوق الكنز.
  * `playVictoryFanfare()`: نغمة نصر قصيرة ومبهجة عند إتمام المرحلة.
* تخزين حالة كتم الأصوات في `SharedPreferences` بمفتاح `kids_sfx_muted` مع زر كتم سريع في إعدادات المسار.

### 4.5 شاشة الاحتفال بالإنجاز (`KidsGamifiedCompletionPage`)
* تساقط النجوم ثلاثية الأبعاد بفيزياء ارتدادية في وسام الطفل.
* ألعاب نارية وكونفيتي ملونة مع زرين بارزين:
  * "المهمة التالية مباشرة يا بطل!" 🚀
  * "العودة لرؤية طريقي على الخريطة" 🗺️ (لمشاهدة قفزة الأفاتار الحية).

## 5. حصر الأصول واستراتيجية التحميل (Asset Inventory & Loading Pipeline)

### 5.1 حصر الأصول وتصميم البدائل البرمجية (Asset Inventory & Canvas Fallbacks)
لتجنب الاعتماد الكلي على إنتاج الصور الفوري، يصمم النظام بـ **Dual-Mode Rendering**:
* دعم أصول الصور والرسومات ثلاثية الأبعاد (Sprites/WebP).
* توفير بدائل برمجية مرسومة ذاتياً بالكود بالكامل عبر `CustomPainter` (Procedural 2.5D Fallbacks) بحيث تعمل اللعبة وتظهر بكامل بهائها حتى لو لم تكتمل كل ملفات الصور فوراً.

#### الأصول الرسومية المطلوبة:
* **البيئات (3 عوالم):** خلفية السماء وعناصر الزينة الطافية (سحب، فراشات، نخيل، كويكبات).
* **المحطات (4 أنواع):** بيت الحفظ بحالاته، صندوق الكنز (مغلق/مفتوح)، قلعة المراجعة، قصر السورة.
* **الأفاتار والرموز:** حركات الأفاتار (Idle, Jump, Listen, Celebrate) وقناديل التكرار.

### 5.2 استراتيجية التحميل المسبق التدريجي (Progressive Precache)
* في `initState` لخريطة المسار، يتم استدعاء `precacheImage` فقط لأصول العالم النشط حالياً (`activeBiome`) وأصول الأفاتار الأساسية.
* يتم تحميل أصول العوالم الأخرى بشكل كسول (Lazy Loading) عند انتقال الطفل الفعلي لسورة في عالم جديد.

```
المرحلة 1: KidsBiomeEngine + KidsAudioFeedbackService + إدارة كتم الصوت (البنية التحتية)
المرحلة 2: خريطة المسار 2.5D (IsometricJourneyPath + InteractiveMapNodes) خلف Feature Flag
المرحلة 3: محرك الأفاتار التفاعلي (HeroAvatarController) مع قفزة Bezier والتمركز التلقائي
المرحلة 4: ترقية لوح الحفظ القرآني وقناديل التكرار في KidsGamifiedListenPage
المرحلة 5: شاشة الاحتفال المحسنة (KidsGamifiedCompletionPage) + تفعيل الميزة افتراضياً
```

## 7. الأداء وخطة الاختبار والتحقق (Performance & Verification)

### 7.1 ضمان الأداء السلس (60-120 FPS)
* عزل المسار والبيئة بـ `RepaintBoundary` لمنع إعادة رسم الكانفاس عند تحرك الأفاتار.
* استخدام الكاش المؤقت للرسومات والمسارات الرياضية لتفادي إنشاء كائنات `Path` مكررة داخل `paint()`.

### 7.2 خطة الاختبار والتحقق (Verification Plan)
1. **Unit Tests:**
   * اختبار `KidsBiomeEngine`: التأكد من إرجاع الثيم الصحيح لكل سورة وجزء (93..114 سحاب، 78..92 واحة، <78 نجوم).
   * اختبار دالة اشتقاق نوع العقدة `resolveNodeType` (عادية، صندوق كل 4، قلعة للمراجعة، قصر للختام).
   * اختبار `KidsAudioFeedbackService` وتخزين واسترجاع حالة الكتم من `SharedPreferences`.
2. **Widget Tests:**
   * اختبار رسم المسار ثلاثي الأبعاد وعقد المحطات المختلفة وتفاعل النقر.
   * اختبار شاشة الحفظ وتوهج قناديل التكرار.
   * التحقق من ثبات التنسيق وعدم حدوث Overflow على مختلف مقاسات الشاشات (360dp إلى 768dp Tablet).
3. **Manual & Device Verification:**
   * اختبار تفاعلي كامل لدورة الحفظ والقفز وتفاعل الأصوات واللمس.
