# Talia — Unified Remediation Plan (الحل التنفيذي الموحد)

**Date:** 2026-08-23 · **Source:** merges `docs/talia_development_quality_audit_2026-08-22.md` (Rev 4) + the external critiques (all claims re-verified against code before inclusion) + the project's Islamic knowledge base (`.agents/talia_islamic_knowledge_skill`) rule IDs.
**Scope note:** development-stage plan. No release verdict. Phases are ordered by dependency: content-safety first (nothing downstream should build on unverified religious text), then data-loss P0s, then governance, then sync/UX hardening, then engineering quality.

## Phase 0 — بوابة سلامة المحتوى (تُنفَّذ أولاً — قبل أي عمل آخر على المحتوى)

> الهدف: أي نص ديني يظهر للمستخدم يرجع لمصدر معتمد قابل للتدقيق، أو لا يظهر.

### R-01 — إيقاف تعديل نص القرآن في مسار العرض (CO-10)
- **المشكلة:** `QuranTextDisplayFormatter.cleanAyahForMemorization` (`lib/core/utils/quran_text_display_formatter.dart:20-55`) يعيد كتابة نص الآية (يحذف علامات نهاية الآية، يعدّل مسافات الترقيم، **يضيف مسافات قبل "ال"**، يدمج المسافات) قبل عرضه في شاشة الحفظ (`lib/core/widgets/qcf_hifz_verse_view.dart:159,263`) — مخالفة QUR-01/HAL-02.
- **الإصلاح:**
  1. اكتب اختباراً يمرّر كل آية من `quran.json` على الـformatter ويقارن الناتج بالمدخل حرفياً — سيكشف حجم التعديل الفعلي (report أول).
  2. القرار المبدئي: **أوقف كل التعديلات عدا حذف علامة رقم الآية الزائدة إن وجدت** (علامة ﴿﴾/الرقم ليست نص الوحي بل ترقيم طباعي — سابق خلافها ضعيف، لكن وثّق القرار).
  3. أي تسوية مسافات مطلوبة فعلاً لعرض خط QCF تنتقل لطبقة render مُختبرة باختبار byte-diff مقابل الـdataset، باسم صريح (مثل `QcfLayoutNormalizer`) وليس "formatter" عاماً.
- **القبول:** اختبار "rendered == dataset (باستثناء علامة ترقيم الآية الموثقة)" أخضر لكل الـ6,236 آية.

### R-02 — إزالة النصوص الدينية المكتوبة يدوياً من الكود (CO-8 — 5 أسطح)
- **المشكلة:** آيات وأدعية وأحاديث hardcoded: `azkar_page.dart:367-426` (9 آيات + 9 أحاديث)، `notification_service.dart:49-53` (3 أدعية fallback)، `certificate_widget.dart:438` (آية الإسراء 9)، `settings_notification_tiles.dart:730` (دعاء)، + اقتطاع الدعاء في الإشعار عند 177 حرفاً (`notification_service.dart:838-843`).
- **الإصلاح:**
  1. الآيات: تُجلب من `quran.json` **بمعرّف (surah, ayah)** — لا نص مكتوب. الشهادة تجلب الإسراء 9 من الـdatasource.
  2. الأذكار/الأدعية/الأحاديث: تُضاف كسجلات في `azkar.json` (بعد R-12 للـschema) وتُعرض بالمعرّف. ما لا يوجد له مصدر معتمد بدرجة — **يُحذف من الواجهة** (HAL-07: الفراغ أفضل من غير الموثق).
  3. الاقتطاع: يُمنع اقتطاع نص ديني؛ البديل عرض أول جملة كاملة أو عنوان قصير غير ديني + فتح الصفحة للنص الكامل.
  4. fallback إشعار الدعاء اليومي عند فشل المصدر: نص عام غير ديني (مثل "افتح أذكار اليوم") بدل دعاء hardcoded.
- **القبول:** grep عربي ديني في `lib/` = صفر خارج (l10n + datasets + المفاتيح)؛ lint البند R-21 أخضر.

### R-03 — manifest حوكمة للبيانات الدينية (CO-12)
- **الإصلاح:** أنشئ `assets/data/manifest.json` (أو `docs/content_manifest.md`): لكل ملف بيانات — المصدر (URL + edition)، الإصدار/تاريخ السحب، الترخيص، الرواية (Hafs 'an 'Asim)، **SHA-256 للملف**، حالة المراجعة البشرية (اسم المراجع + التاريخ + النطاق، عند توفره). سكربت CI يتحقق أن الهاش الفعلي = المثبّت.
- **ملاحظة إطار:** الهاش الحالي لـ`quran.json` يُحسب مرة ويُثبّت — الهدف تثبيت الحالة الراهنة وجعل أي تغيير مستقبلي مرئياً وقابلاً للمراجعة (KB `18` Engineering Implications).
- **القبول:** أمر `dart run tools/verify_content_manifest.dart` (أو ما يعادله) يمرّ؛ تغيير بايت واحد في quran.json يُفشل الـCI.

## Phase 1 — عيوب P0 الهندسية (فقدان بيانات + عقد مكسور)

### R-04 — `revoke_guardian_link` (P0-1)
- **الإصلاح:** migration جديدة: RPC بالتوقيع `revoke_guardian_link(p_counterpart_user_id uuid)` — تتحقق أن المستخدم طرفاً في رابط نشط (أياً كان اتجاهه)، تضبط `status='revoked'`, `revoked_at=now()`، SECURITY DEFINER، `search_path=public`، revoke من anon. تُطبَّق على قاعدة المشروع المستضافة + تُضاف لـ`scripts/verify_supabase_contract.ps1`.
- **القبول:** ربط طفل ثم فك الربط من الواجهة ينجح؛ الصف في `parent_child_links` يصبح revoked؛ إعادة الربط تعمل؛ سكربت العقد يشمل الـRPC ويمرّ.

### R-05 — فصل البسملة عن آية 1 (P0-2) — بطريقة مصدرية لا Runtime Regex
- **الإصلاح (مُحسَّن بعد المراجعة):**
  1. سكربت استيراد واحد (`scripts/fetch_quran.dart` يُطوَّر أو سكربت جديد `tools/build_quran_dataset.dart`) يقرأ المصدر الخام، **يفصل البسملة كحقل `bismillahPrefix` (أو `headerText`)** على مستوى السورة ويكتب `quran.json` نهائياً — **الملف الخام الأصلي يُحتفظ به كما هو** (raw mirror) للمراجعة والتدقيق.
  2. الفصل يطابق **نمطي التشكيل** (`بِسْمِ` و`بِّسْمِ` في 95/97) بمقارنة بعد تطبيع الحركات، ويطابق فقط في السور ≠ 1، 9.
  3. الـdatasource يقرأ الحقلين كما هما — **صفر تحويل وقت تشغيل**.
  4. العرض: البسملة تُعرض كترويسة غير مرقمة (كما في صفحة QCF).
  5. اختبارات: S1V1 وS9V1 لم يتغيرا؛ 112 سورة نُظّفت؛ S2V1 يبدأ بـ`الٓمٓ`؛ golden لكارت الخطة اليومية لسورة البقرة؛ **اختبار أن النص الخام + الحقل المفصول == النص الأصلي** (إثبات عدم ضياع أي بايت).
- **القبول:** كل الاختبارات أعلاه أخضر + تحديث SHA-256 في manifest (R-03) مع مراجعة.

### R-06 — بوابة تسجيل الخروج تغطي كل النطاقات (P0-3)
- **الإصلاح:** تجميع واحد `PendingSyncState`/دالة `hasPendingSyncWork()` موحّدة في `CloudSyncCoordinator` تغطي: bookmarks، identity، certificates، kids، rewards، streaks/xp/activities — و`flushBeforeSignOut` (`lib/features/auth/application/cloud_sync_coordinator.dart:137`) ترجع false إن كان أي نطاق غير مؤكد.
- **القبول:** اختبار تكامل: offline → bookmark جديد → تعطيل RPC → محاولة خروج → `AuthSignOutBlockedPendingData`؛ الخروج القسري يحتفظ بصف الـqueue؛ بعد إعادة الدخول والاتصال: سجل واحد سحابياً ومطابقة محلي/سحابي.

## Phase 2 — نموذج بيانات دينية محكوم (KB compliance)

### R-07 — ترقية schema الأذكار (CO-4)
- **المشكلة:** 0/85 درجة توثيق، 73/85 مرجع بلا رقم قابل للحل، والكيان `Zikr` (`lib/features/azkar/domain/entities/azkar_entities.dart:5-30`) لا يستطيع تمثيل البيانات أصلاً.
- **الإصلاح:**
  1. حقول جديدة إلزامية في `azkar.json` + `Zikr`: `sourceType` (quran/hadith/athar/guidance)، `sourceCitation {collection, book?, number}` (قابلة للحل)، `authenticityGrade` (من المصدر فقط — لا استنتاج داخلي أبداً، HAD-03)، `gradedBy?`، `tier?` (للأدعية: quranic/prophetic/guidance — CO-9)، `reviewStatus`، `datasetVersion`.
  2. إعادة استيراد من مصدر يحمل الدرجات — المرشح الأول حسب KB `18`: **الدعاء والأذكار بمصادر الدعاء** (الجامع الصحيح)؛ Hisnul-Muslim JSON المجتمعي مصدر مساعد يُدقّق عينة منه مقابل الدعاء.
  3. الواجهة تعرض المصدر + الدرجة (تعمل بالفعل للمرجع — `azkar_category_page.dart:196,283,575` — تُمد بالدرجة).
  4. **ملاحظة إلزامية (KB GOV-01/14):** استيراد الدرجات النهائية يحتاج اعتماد مراجع محتوى مؤهل — الخطة تنفّذ البنية والاستيراد الأولي، والاعتماد يُسجّل في manifest.
- **القبول:** 85/85 (أو أقل بعد حذف غير الموثق) سجل بدرجة + مرجع قابل للحل؛ اختبار يفشل CI عند أي سجل جديد بلا درجة/مرجع.

### R-08 — حقل `tier` للأدعية (CO-9) — يُنفَّذ ضمن R-07.

### R-09 — السجدات برواية العدّ (CO-3)
- **الإصلاح:** بيانات سجدات من مصدر معتمد، موسومة برواية العدّ: **14 متفق عليها + 1 مختلف عليها (الحج 22:77 مقابل ص 38:24)** — العرض يوسّم ولا يثبّت رقماً واحداً (KB `01`). مؤشر هادئ في القارئ.
- **القبول:** اختبار: 14+1؛ الآية المختلف عليها تحمل وسم الخلاف؛ عرض المؤشر في القارئ.

### R-10 — الحزب من بيانات الأرباع (CO-2)
- **الإصلاح:** استبدال تقريب منتصف الصفحة (`lib/core/utils/mushaf_hizb_helper.dart:59-68`) ببيانات `quarters.dart` (240 ربعاً) داخل qcf_quran_plus — حقول مصدرية لا حساب (`01` Practical Rules).
- **القبول:** اختبار حدود: أول آية من كل حزب/ربع صحيح مقابل البيانات؛ صفر heuristics.

### R-11 — رفض الصفوف التالفة بدل التخمين (CO-5)
- **الإصلاح:** `quran_local_datasource.dart:85` وأخواتها: أي صف ناقص `page`/`juz`/رقم عام → رفض الصف + سجل خطأ صريح، لا `surah.page + i/15`.
- **القبول:** حقن صف تالف في نسخة اختبار → فشل واضح برسالة، لا قيم مخمّنة.

## Phase 3 — تصلبيـن المزامنة والخصوصية والسياسات

### R-12 — إظهار الرسائل الميتة + تصنيف الأخطاء (P1-4, SY-5, SY-6)
- **الإصلاح:** لافتة/شاشة حالة مزامنة في الإعدادات تعرض dead letters مع زر "أعد المحاولة الآن" يوصله بـ`recoverDeadLetter(kind)` + `run()`؛ `markFailure` يفرّق retryable (شبكة/5xx) عن دائم (4xx) ولا يحرق محاولات على الدائم؛ `default: return true` للأنواع غير المعروفة تصبح فشل/quarantine مع سجل.
- **القبول:** محاكاة 8 إخفاقات → اللافتة تظهر → استعادة → المزامنة تنجح؛ 4xx لا يستهلك محاولات.

### R-13 — مكافآت الوالدين عبر الـqueue (P1-6)
- **الإصلاح:** نوعا `parentRewardsPush/Pull` + مفتاح idempotency (UUID محلي ثابت للإنشاء offline) + دمج بالمعرف والحالة عند السحب بدل الاستبدال الكامل (`memorization_kids_cloud_sync_service.dart:91-99,273-423`).
- **القبول:** offline unlock → reconnect → دمج صحيح؛ لا overwrite للقائمة المحلية.

### R-14 — قرار STT الصريح + مسار التقييم اليدوي (P1-9, UX-11)
- **الإصلاح:** (أ) `onDevice: true` مع فحص التوافر + fallback، أو (ب) تعديل فقرة الصوت في سياسة الخصوصية لتطابق الواقع — **والاثنان يبدآن بـ**: مسار self-grade يدوي (ممتاز/متوسط/ضعيف → نفس mapping `session_adapters.dart:63-67`) عند `V2SpeechIssue != null`، للأطفال والكبار.
- **القبول:** وضع الطيران: تعرّف يعمل على جهاز يدعم on-device؛ جهاز لا يدعم: الإكمال اليدوي ينجح والـXP/streak تُمنح؛ نص السياسة مطابق للسلوك في AR/EN.

### R-15 — عتبة تقييم مستقلة للأطفال (CO-11)
- **الإصلاح:** config منفصل صريح (مثل `KidsRecitationPolicy(passThreshold: 0.85…)` — القيمة النهائية قرار تربوي) بدل `const V2RecitationEvaluator()` الافتراضي في `kids_mode_cubit.dart:80` (KB `12`:20,30,45,57).
- **القبول:**Kids يمرر بعتبة أخفض من البالغين؛ اختبار يفشل لو وحّدت العتبتان مستقبلاً (guard test على config منفصل).

### R-16 — إنجاز الإنجليزية للأسطح المتبقية (P1-7)
- **الإصلاح:** الإشعارات (تمرير locale/نصوص محلّية إلى `NotificationScheduler`)، شهادة الاحتفال/المشاركة، الدليل التعليمي — إلى arb؛ إلغاء `SocialShareCopy`.
- **القبول:** sweep لقطات EN: صفر عربي في الإشعارات/الشهادة/المشاركة/الدليل.

## المرفوض من المراجعة الخارجية (غير موجود في حزمة المعرفة — قرار منتج، ليس التزاماً)

1. **"الآية الضعيفة = متوسط آخر 3 تقييمات"** — لا يوجد في KB 06/07. الوضع الحالي (آخر تقييم + عدّاد lapses + كشف leech) مقبول؛ إن أردت المتوسط فهو تحسين تربوي مقترح — يُقرَّر ثم يُهاجر تاريخ التقييمات، ليس "إصلاحاً".
2. **"كل مراجعة تبدأ بالاستدعاء قبل الاستماع"** — KB 07 يطالب بترجيح weak/overdue في **الترتيب** (منفَّذ في ReviewClassifier) لا بفرض تسلسل داخل الجلسة. قرار تصميم جلسة، ليس مخالفة.
3. **"SM-2 غير مطابق"** — تطبيقك معدَّل بوعي (soft-lapse بدل reset). KB 06:11 يصف SM-2 بـ"reset on failure" — الحل: وثّق العقد الفعلي (اسم صريح مثل "SM-2-lite/modified" + شرح soft-lapse) في `README`/KB بدل تغيير الخوارزمية. DOCUMENTATION_DRIFT لا defect.
4. ملاحظة ترتيب الخطة اليومية (الجديد قبل القريب/البعيد): KB 07:49 يقصر الترجيح على طابور المراجعة؛ ترتيب الخطة اليومية قرار منتج — إن أردت مواءمتها مع KB فعّل weak/overdue أولاً في `memorization_daily_plan_service` بقرار موثق.
